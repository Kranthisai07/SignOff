# decisions.md — Decision log

Append a new entry at the time of each real decision, bug, or approach swap. Format: **What / Why / Alternatives considered.** Skip mechanical changes.

## D-001 (Oct 26) — Build a verifier + open benchmark, not another assistant
- **What:** Signoff verifies hands-on steps and publishes a benchmark (false-pass rate, cost per correct verdict). The glasses app is the demo.
- **Why:** Live AI and the Display's guidance already cover "talk me through a task". Verification with a measured error rate is new, fits Push the Frontier, and scores on Technical Depth and Meta-tooling use.
- **Alternatives:** Extend the user's SourceMind (rejected: new-work-only rule for Indie, and "basic RAG" is an anti-project); a pure model-router benchmark (safer but no glasses story, weaker demo).

## D-002 (Oct 26) — Name: Signoff (formerly "Witness")
- **What:** Use "Signoff". **Why:** says what it does, and the key metric (false-pass) is the risk of signing off too early; "Witness" is an established human-rights org and hard to search/own on X (matters for the viral bonus). **Alternatives:** Proofstep, Plumbline. Availability of GitHub/X/domain not yet checked.

## D-003 (Oct 26) — Android phone + Windows + Android Studio for the glasses app
- **What:** Build the capture app in Kotlin from Meta's CameraAccess sample; backend in Python. **Why:** Android toolchain works on Windows; iOS needs Xcode/Mac and signing overhead. **Alternatives:** iOS app (rejected for time), Flutter community plugin (unverified, risky).

## D-004 (Oct 26) — Developer Mode with "0" IDs
- **What:** Set `APPLICATION_ID` and `CLIENT_TOKEN` to "0"; no Wearables Developer Center project. **Why:** Meta's Android integration guide says attestation is not used in Developer Mode; demo runs on own phone. **Alternatives:** Register an org/project for real IDs (needed only for non-Developer-Mode / test-user sharing).

## D-005 (Oct 26) — De-scope to 2 procedures, about 25 runs; glasses live loop is a Should
- **What:** Must = benchmark + verifier on recorded clips + demo video. Live glasses = Should, gated by G3 (decide by end of Oct 28). **Why:** solo, limited credits, preview SDK; the benchmark does not depend on live streaming. **Alternatives:** Full 3-procedure, 40-run plan with voice and Wonder arm (rejected as ungrounded for the resources).

## D-007 (Oct 28) — Build with Qwen via OpenRouter instead of Sonnet
- **What:** Point Claude Code at OpenRouter (`ANTHROPIC_BASE_URL=https://openrouter.ai/api`) and use `qwen/qwen3-coder-plus` for coding; Sonnet only as an approved fallback. **Why:** cut dev cost while the Meta credits ($150) are reserved for product runtime. **Alternatives:** stay on Sonnet (more reliable, higher cost); Muse Code (Meta's coding agent; plan/pricing unverified). **Risks:** OpenRouter warns Claude Code may not work correctly with non-Anthropic models; tool use/subagent behavior with Qwen untested; "similar to Sonnet 5.5" is the user's belief, not measured. Gate G-1 decides.

## D-008 (Oct 28) — Meta models only in the product runtime
- **What:** Signoff's code path calls only Meta models (Muse Spark, SAM 3.1, optional Wonder, Spark Open via partner); Qwen is a development tool only. **Why:** Stage 1 judging is pass/fail on using Meta Model API and/or open-weight models, and Meta tooling is 25% of the score. **Alternatives:** use Qwen as a cheaper verifier (rejected: could fail Stage 1 and wastes the scoring criterion).

## D-010 (Oct 28) — Bug: `.env` parser sent quoted key, causing 401 `invalid_api_key`

## D-011 (Oct 29) — Switch G1 test procedure from oil check to fried egg
- **What:** G1 uses a fried-egg SOP (`data/sop_fried_egg.md`, 5 steps, 10 photos) instead of the engine oil check. **Why:** on the 10 oil photos (`eval/g1.py`) Spark returned fail on all 10 and its reasons said the dipstick holes and oil line were too small and far to read in wide shots, so the task tested photo framing, not verification. The plan already says to prefer procedures with large visual differences. **Alternatives:** retake the oil photos as close-ups (cheaper only if the user stays on oil; still a thin-rod detail); pour-over coffee; PC/laptop cable task. The 10 oil photos and verdicts stay in `data/raw/` and `runs/g1/verdicts.jsonl` as a finding: small details in wide shots are unreadable for Spark.

## D-012 (Nov 2) — Video-first pipeline while waiting for footage
- **What:** `labels.csv` gets 3 extra columns (`video`, `t_start`, `t_end`) beyond the specs §4 label row; the harness samples 3 frames per step from the labeled time range with ffmpeg (or takes a single photo if `video` is a jpg/png). Step verdict = `combine(frame verdicts)`: any fail -> fail, any unsure -> unsure, else pass. Verdicts are cached by sha256(frame, step text, model, prompt version) in `results/cache/`. **Why:** the user can only supply a video this evening; time ranges let one video yield many labeled step rows. The combine rule is biased against false passes, the project's headline metric; it is a design choice, not tuned. **Alternatives:** majority vote across frames (fewer false fails, more false passes); per-frame scoring (inflates N, frames of one step are not independent); `python-dotenv`/OpenCV (not needed, ffmpeg is installed). Known limit: frame sampling is evenly spaced, so a short key moment can be missed.

## D-013 (Nov 3) — Drop the "Brown Edge" photo from the labeled set
- **What:** Removed the `egg_s4_fail_1.jpg` row from `data/labels.csv` at the user's request. The file stays in `data/raw/`. **Why:** the user and I both could not see dark or burnt edges on the egg (the browning is on the pan), so the fail label was doubtful, not a clear model error. **Effect to disclose:** it was the only miss, so the rows went from 9/10 to 9/9 accuracy. That 9/9 comes from removing the one hard case, so any public report must say the row was dropped for label ambiguity, and that N is 9 with wide intervals (accuracy Wilson 95% [0.701, 1.0]). **Alternatives:** keep it as a miss (honest on Spark, but the ground truth is unclear); relabel it pass (no, the user named it "Brown Edge"); re-shoot a clearly burnt egg (done: `egg_s4_fail_2.jpg` is kept and Spark caught it).
